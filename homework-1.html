HMWK 1 — Private key → public key on a toy elliptic curve

We use the toy curve y² = x³ + 7 (mod 17) and the base point G = (1, 5). A private scalar k produces the public point Q = kG, where multiplication means repeated elliptic-curve point addition.

For distinct points: λ = (y₂ − y₁)/(x₂ − x₁) mod 17
For doubling: λ = (3x₁²)/(2y₁) mod 17
x₃ = λ² − x₁ − x₂ mod 17;   y₃ = λ(x₁ − x₃) − y₁ mod 17

Division modulo 17 means multiplication by a modular inverse. The point at infinity is written O and acts as the identity.

What do the statistics tell us?

  • Uniformity within this subgroup: if k is selected uniformly from 1 to 8, each of the eight non-infinity subgroup points occurs once. In this example every x-coordinate (1, 2, 5, 12) appears twice, while every y-coordinate in the table appears once.
  • Bits and correlations: the bit counts are not balanced, and x and y are not independent random bit strings. The curve equation constrains which points can occur; additionally, k and 9−k have the same x-coordinate and opposite y-coordinates modulo 17.
  • Input/output relation: the mapping k → kG is deterministic and has group structure. A small change in k moves to another group point, but there is no guarantee that half the output bits change.
  • Connection to one-way functions: for a properly chosen, large elliptic curve, computing Q = kG is efficient, while recovering k from Q is believed to be computationally infeasible (the Elliptic Curve Discrete Logarithm Problem, ECDLP). This is the relevant one-way property for public-key cryptography.
  • Different from a hash: a cryptographic hash accepts arbitrary-length input and produces a fixed-length bit string. It is designed for properties such as preimage resistance, collision resistance and avalanche behavior. Scalar multiplication instead outputs a point in a specific group and is used to form public keys and digital signatures. This tiny example is far too small to test real cryptographic security.
